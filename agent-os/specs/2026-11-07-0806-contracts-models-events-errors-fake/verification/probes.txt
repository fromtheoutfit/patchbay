Probes of pydantic, numpy and mypy at the versions uv.lock resolves, run 2026-11-07 on branch
feature/10-contracts-instrument-protocol-models-errors-events-and-the-fakeinstrument-reference-implementation, before any of the spec's modules was written. Each probe is a scratch
script outside the repository (the session's scratchpad, shown here as probes/<name>.py), run from
the repository root through the locked environment: python as `uv run --locked python <script>`,
mypy as `uv run --locked mypy <script>`, so mypy reads this repository's [tool.mypy] (strict,
3.12, warn_unreachable) and checks the one file named. Each script's source is shown before its
output, so the setup can be read; each case prints its label and either "ok -> <result>" or the
exception's type and first lines. The cases are chosen to tell the competing claims apart: the
refusal beside the acceptance, the Python input beside the JSON, the form chosen beside the one
not chosen.

Versions: python 3.12.16, pydantic 2.14.3, pydantic-core 2.50.4, numpy 2.5.4, mypy 2.4.1 (compiled: yes).

What the design took from them (shape.md, Decisions):

- runtime.py 1-2: a Mapping field validates to a dict, mutable inside a frozen model, unhashable;
  held as MappingProxyType it refuses item assignment, and pydantic cannot serialize it without
  the wrap serializer (PydanticSerializationError), which hands it a plain dict and round-trips.
- runtime.py 3: bytes in JSON default to utf8 and fail on non-UTF-8 bytes; base64 round-trips any
  bytes, empty included.
- runtime.py 4: an NDArray[np.float32] arbitrary-type field is an isinstance check of ndarray (a
  float64 array passes, so the dtype needs its own validator); == on two models holding distinct
  arrays raises ValueError, hash raises TypeError, model_dump_json raises; writeable=False makes
  the array refuse assignment.
- runtime.py 5, strict_nested.py, config_form.py: strict admits an int for a float in Python and
  JSON input and refuses a str for a float, int, bytes or enum, a bool for an int, an int for a
  bool, a float for an int, a list for a tuple, a bytearray for bytes, NaN and inf. Two results
  differed from the plan and went to the owner: a dict for a nested model is accepted in Python
  input, every field inside it still strict (a str for a float or an enum, a bool for a float,
  refused at depth); and model_validate_strings parses "0.5" as a float, its purpose. The owner
  accepted both as pydantic's strict. pydantic.InstanceOf would have required instances; not used.
- runtime.py 6: assignment to and deletion of a frozen model's field raise pydantic's
  ValidationError, a ValueError subclass: PatchbayModel wraps __setattr__ and __delattr__.
- runtime.py 7: runtime_checkable isinstance accepts a data member as an attribute or a property
  and refuses an object missing one; issubclass is refused for a Protocol with a data member; any
  callable, of any arity, is an instance of a callable Protocol.
- typing_probe.py: a base model that overrides __init__(self, /, **data: object) still leaves
  mypy a synthesized, typed, keyword-only __init__ on each subclass (A, B, J); mypy does not see
  frozen set through model_config (C passes) but does through the class keyword (D); PresetKey
  and str are refused where ParameterId is expected (E, F); a PEP 695 Subscriber[E: Event] is
  contravariant (G accepted, I refused) and its positional-only parameter frees the handler's name
  (H).
- frozen_kw.py, frozen_kw2.py, config_form.py: with frozen=True as the base's class keyword, mypy
  refuses a subclass that does not repeat it ("Non-frozen dataclass cannot inherit from a frozen
  dataclass"); repeated on each, mypy refuses assignment (K, L, N) and the __init__ stays typed
  (M). The class keyword and model_config merge at runtime. The owner chose the class keyword on
  every model. config_form.py's last line assigns on purpose: mypy refuses it (the error below),
  and at runtime it raises, so its traceback closes that script's output.

from typing import NewType, Protocol, runtime_checkable

from pydantic import BaseModel, ConfigDict, ValidationError


class Base(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", strict=True)

    def __init__(self, /, **data: object) -> None:
        try:
            super().__init__(**data)
        except ValidationError as error:
            raise RuntimeError(str(error)) from error


class Quantity(Base):
    value: float
    unit: str


class KwFrozen(BaseModel, frozen=True):
    value: float


Quantity(value=1.0, unit="hz")

Quantity(valu=1.0, unit="hz")  # B: should be refused (unknown keyword)
q = Quantity(value=1.0, unit="hz")
q.value = 2.0  # C: refused only if mypy sees frozen through model_config
k = KwFrozen(value=1.0)
k.value = 2.0  # D: refused if mypy sees the class keyword frozen=True

PresetKey = NewType("PresetKey", str)


def take(pid: ParameterId) -> None: ...


take(PresetKey("x"))  # E: refused
take("x")  # F: refused


class Event:
    pass


class Changed(Event):
    pass

class Subscriber[E: Event](Protocol):

def on_changed(e: Changed) -> None: ...


def want_changed(s: Subscriber[Changed]) -> None: ...

probes/models_init.py (added while writing models.py, the same day)
================================================================================

The first draft of PatchbayModel overrode __init__ to wrap pydantic's ValidationError, and a
Patch's JSON round trip failed: "unit: Input should be an instance of Unit", with no path. pydantic
marks a model whose __init__ is not BaseModel's as custom_init (its _model_construction.py, line
146: `cls.__pydantic_custom_init__ = not getattr(cls.__init__, '__pydantic_base_init__', False)`)
and then builds a nested model by calling that __init__ with the parsed input, in Python mode, so
strict refuses JSON's enum string and a nested refusal loses its location. BaseModel's own
__init__ carries `__pydantic_base_init__ = True` (main.py, line 290). PatchbayModel's __init__
validates exactly what BaseModel's does and then wraps the refusal, so it carries the same
marker: nested models are validated by pydantic, a constructor call still runs the override.
The probe shows both forms, the calls made to __init__ and the error locations.

"""A model's own __init__ and nested validation: without and with pydantic's base-init marker."""
import enum
from typing import Any

from pydantic import BaseModel, ConfigDict, ValidationError


class Unit(enum.StrEnum):
    ratio = "ratio"


calls: list[str] = []


class Plain(BaseModel, frozen=True):
    model_config = ConfigDict(strict=True)

    def __init__(self, /, **data: object) -> None:
        calls.append(type(self).__name__)
        super().__init__(**data)


class Marked(BaseModel, frozen=True):
    model_config = ConfigDict(strict=True)

    def __init__(self, /, **data: object) -> None:
        calls.append(type(self).__name__)
        super().__init__(**data)

    __init__.__pydantic_base_init__ = True  # type: ignore[attr-defined]


class PlainQ(Plain, frozen=True):
    unit: Unit


class MarkedQ(Marked, frozen=True):
    unit: Unit


class PlainOuter(Plain, frozen=True):
    q: PlainQ


class MarkedOuter(Marked, frozen=True):
    q: MarkedQ


def case(label: str, fn: Any) -> None:
    calls.clear()
    try:
        out = repr(fn())
    except ValidationError as e:
        out = f"ValidationError at {[err['loc'] for err in e.errors()]}: {e.errors()[0]['msg']}"
    print(f"  {label}: {out}; __init__ called for {calls}")
